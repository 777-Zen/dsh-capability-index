# capabilityIndex.declarations 能力声明契约 v1.1

> 本文件是 `dsh-capability-index` 与能力提供方（任何插件）之间的**独立契约文档**，
> 与实现解耦：解析器（`lib/core.js#parseDeclarations`）来源无关——无论声明来自
> 运行时 provide、未来的静态声明槽（package.json 扩展字段）还是其他载体，
> 只要形状符合本契约即可被消费，接入新来源不碰 core。
>
> 版本约定：本契约遵循语义化表述；消费端承诺**向后兼容**下述全部历史形状。
> **v1.1（2026-08-26）**：`not_for` 从纯展示文案升级为有执行语义的核对闸
> （见 §5）；新增可选显式补词字段 `not_for_keywords`。

## 1. 发布通道

```js
// 插件 apply(ctx) 内：
ctx.provide('capabilityIndex.declarations', {
  version: '1.0',          // 推荐显式携带
  declarations: [ /* 条目，见 §2 */ ],
})
```

- **单聚合器约定（v0 起）**：每个组合（composition）只应有一个插件提供该服务。
  多来源聚合是后续演进项；当前第二个提供方的行为未定义（不保证合并）。
- 未启用的插件不加载、不 provide → 其声明自然不进索引。这是隐私边界的实现基础：
  索引只看见"当前会话模型可见"的工具与声明。

## 2. 载荷形状（消费端全部兼容）

| 形状 | 示例 | 说明 |
|---|---|---|
| **v1（推荐）** | `{ version: '1.0', declarations: [...] }` | 字符串版本号 |
| v0 数字版本 | `{ version: 2, declarations: [...] }` | 历史形状，样例插件在用 |
| 无版本 | `{ declarations: [...] }` | 兼容 |
| 裸数组 | `[...]` | 兼容 |

## 3. 声明条目字段

```js
{
  tool: 'concat_text',            // 必填，string：目标工具名（须与注册名一致）
  keywords: ['拼接', 'join'],     // 可选，string[]：消息词面命中 → 排序加分
  use_when: '把多段文本拼到一起', // 可选，string：命中时渲染进提示块（集中渲染）
  not_for: '数值相加、文件重命名', // 可选，string：反向边界（v1.1 起参与执行核对，见 §5）
  not_for_keywords: ['重命名'],    // 可选，string[]（v1.1）：显式补词，缺省自动分词
  min_complexity: 'low',          // 可选，'low'|'mid'|'high'：任务量级门槛（不过则不推）
  lang: 'zh',                     // 可选，string：词条语言标记（多语言并集预留）
}
```

字段语义：

- `tool` 非字符串的条目**跳过**（不报错）；同名条目后者覆盖前者。
- `keywords` 参与排序打分；`use_when` 只参与渲染、不影响判定与排序；
  `not_for` 自 **v1.1 起**除渲染外还参与守门闸执行核对（§5），
  `not_for_keywords` 是它的显式补词通道。
- `min_complexity` 的量级由消息长度 + 子要求数估计（E+D 权重），低于门槛的声明条目
  在排序阶段直接过滤（如 S9：低量级消息不推 high 工具）。
- 无声明的工具不会被歧视出索引：description 全文作为**低置信降级条目**照常参与
  关键词匹配（权重低于有声明条目），提示块中标注"未提供能力声明"。

## 4. 渲染行为（消费端承诺）

命中时消费者把 `use_when` / `not_for` **集中渲染进自己的提示块**
（形如 `- concat_text：…描述…（适用：…；不适用：…）`），全程不改写提供方注册的
工具定义/description/参数——这是 v0 硬边界：只读扫描 + 只注入自己的提示块。

## 5. not_for 执行语义（v1.1 新增：守门闸）

`not_for` 不再只是提示文案——消费者在合议输出与推送落定之间对**携带声明的候选**
执行统一核对（纯函数 `core.applyNotForGate`，配置块 `trigger-table.notForGate`）：

- **双信号**：
  1. 关键词信号——`not_for` 文本分词后与当前用户消息词集求交，非空即命中
     （ASCII 复用工具索引的 token 口径；中文取相邻字二元组；`not_for_keywords`
     显式补词按消息子串匹配）；
  2. 嵌入信号——cosine(消息向量, vec(not_for))，复用插件内置语义引擎。
- **两档动作**：
  - **硬拦**：关键词命中 ∧ 嵌入 ≥ `hardSim` → 该候选从推荐中移除（确定性冲突，
    任何合议路径不再出现）；
  - **软处理**：恰一信号命中，或嵌入落入 `[softSim, hardSim)` → 该候选保留在
    推荐中，但降位到窗口尾部并渲染"⚠️ 声明提示：此场景可能不适用（not_for）"
    警示行——是否采纳仍由模型决定，模型终判权不变。
- **边界（诚实口径）**：
  - 无声明工具**不在保护范围**——`not_for` 无从核对，照常参与推荐；
  - 仅关键词命中而嵌入不可用（语义引擎未就绪/未启用）时只软处理，**绝不硬拦**；
  - `use_when` 不做正向核对（防召回误杀），继续作展示文案；
  - 消费端不改写提供方注册的工具定义/description/参数（v0 硬边界不变）；
  - `enabled: false` 可整体关闭闸门（not_for 退回 v1.0 纯展示行为）。
- 阈值初值经离线扫描确定（`eval-results/calibrate.mjs` 闸门网格维度），
  随样本积累持续校准；每次硬拦/软警示都记入决策日志
  （decisions.jsonl 的 `gateBlocked[]` / `gateWarned[]` 字段）供生产审计。

## 6. 兼容性承诺

- 消费端接受上表全部历史载荷形状；未来新增字段对旧消费端透明（忽略未知字段）。
- 建议声明方显式携带 `version: '1.0'`，为将来破坏性演进留出协商空间。
- 解析器来源无关：静态声明槽（package.json `dsh.capabilities` 等 harness 演进）
  未来接入时只需在新来源处取到载荷再走同一 `parseDeclarations`，core 不改。
